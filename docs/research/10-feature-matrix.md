## 0. 一页结论

**要做的事不是"复刻 PCL2 的所有功能"，而是三件事：**

1. **主链路 100% 可用**——从"空目录"到"整合包进服"这条路，每一步都不能断；
2. **失败处理不掉队**——PCL2 真正的护城河不是功能数量，是它把"崩了怎么办"做成了产品（崩溃分析 3 步、错误报告、下载源自动禁用重试、内存优化）；
3. **联机做成一等公民**——但这条需要一个诚实的提醒，见下面第 1 条发现。

**三个必须先摆到桌面上的发现：**

| # | 发现 | 证据 | 对范围的影响 |
|---|---|---|---|
| 1 | **PCL2 已经有"联机"了**，而且是完整形态：EasyTier 组网 + 房间 + 邀请码 + 社区/自定义节点中继 + NAT 质量提示 + "你比房主网络更好，换你当房主"建议 | `PageLink` / `pagelinkmain.xaml`；字符串"准备初始化 EasyTier""下载联机模块""加入联机房间""正使用社区节点进行中继""房主" | "加联机"**不构成对 PCL2 的差异化**。要么承认这是 parity（那就得比它更稳/更简单），要么重新定义差异化点。这是本文最需要你拍板的一件事（§8 Q1） |
| 2 | **PCL2 未见"备份"，也未见独立"服务器列表"** | 可执行文件 UTF-16 字符串中"备份"0 次、"还原"0 次、"服务器列表"0 次，UI 亦无入口；只有版本级"自动进入服务器"（`JoinServerOnLaunch` + `--server/--port/--quickPlayMultiplayer`） | "PCL2 所有功能"这个目标本身是不完整的：**备份反而是我们可以做出差异的空白**，而服务器列表只需做到"够用"（字符串检索不能证明绝对不存在，发版前再人工过一遍 UI） |
| 3 | **原版下载有上游合规风险** | 公告 230 原文："为遵守相关法律法规，PCL 不再提供 MC 下载功能"；但本机 16:53 实测 1.19 安装成功（走 BMCLAPI） | 下载能力要保留（否则产品不成立），但**必须做成可配置、可关闭、可替换的源适配层**，并把合规结论作为发布闸门（§7 R1） |

**范围结论（数字口径见 §4.6）：**

- **P0 = 17 项，约 163 人日（±25%）**：实例管理、原版安装、Forge/NeoForge/Fabric、下载基础设施、Java 管理、离线/微软/Authlib 三态账户、启动链路、模组/资源包/光影基础管理、整合包安装、服务器自动加入、联机、日志与崩溃报告、更新器（17 项按可测性归并为 §5 的 14 组验收）。
- **P1 = 约 61 人日**（parity 补齐）：OptiFine/LiteLoader、整合包导出、Mod 更新与下载、服务器收藏列表、备份、皮肤、主题基础、帮助/反馈、崩溃规则库增强、更新通道。
- **P2 = 约 21 人日**（可选）：Quilt、自定义主页/音乐、数据包/世界下载、Mod 翻译、遥测。
- 合计约 **245 人日 ≈ 4 人一个季度**（不含设计/QA/本地化，含则 ~306）。

**一句话取舍**：P0 里我宁可砍掉"皮肤、主题、备份、Mod 更新"，也不砍"崩溃报告"和"下载源容错"——因为前者是加分项，后者决定用户第一次失败之后还回不回来。

## 2. 目标用户与场景（从证据反推，不是拍脑袋）

**主画像**：中文整合包玩家，Windows，一台带独显的笔记本/台式，自己攒了十几个实例，玩 100~360 mod 的重整合包，想和朋友一起玩但不想租服务器。

支撑证据：

- 15 个实例、**9 个超过 1.4 GB**、最大 10.8 GB / 311 mods → **实例隔离和扫描性能是刚需，不是优化项**；
- `PCL.ini` 里有 3 张主页卡片（`CardCount:3`、`CardKey1..4`），卡片值是实例名 → 用户把"最近在玩什么"当首页用；
- Java 17/21/25 三套共存，`config.json` 里对单个实例强制 Java 21 → **Java 选择必须是 per-instance 的，全局一刀切会直接崩**；
- 版本 `1.20.4` 的 `PCL\Setup.ini` 写着 `VersionServerAuthName:LittleSkin 登录` / `VersionServerAuthServer:https://littleskin.cn/api/yggdrasil` / `VersionServerLogin:4` → **第三方 Authlib 登录是真实使用中的路径**，不是边角功能；
- 整合包根目录的 `想多人联机游玩？点我点我.txt` 是一张开服广告（58 元/月起）→ **联机需求存在且已在付费**；同时说明"官方联机体验"没接住这批人。

**版本级 `versions\<实例>\PCL\Setup.ini`（实测键）**：`VersionVanilla`、`VersionVanillaName`、`VersionForge`、`VersionNeoForge`、`VersionLiteLoader`、`VersionArgumentIndie(V2)`、`VersionRamType`/`VersionRamCustom`、`VersionArgumentJavaV2`、`ReleaseTime`、`Logo`（`pack://application:,,,/...Images/Blocks/Anvil.png`）、`State`、`Info`、`VersionServerAuthName`/`VersionServerAuthServer`/`VersionServerAuthRegister`、`VersionServerLogin`（`4` = Authlib）、`VersionServerEnter`（自动进服）。

**版本级 `PCL\config.json`**：`InstanceMigratedJava`、`InstanceForcedJava{ Folder, Version{ Major, Minor, Build } }`。

**其它落盘契约**：

- `launcher_profiles.json`：每次启动前重写，写入 `profiles.PCL`、`clientToken`、`authenticationDatabase`、`selectedUser`（第三方工具靠它识别实例）；
- Natives 目录命名：`versions\<实例>\<实例>-natives`（带空格、带中文）；
- 版本 JSON：PCL 倾向**扁平化**写入（`史前世界 2.json` 无 `inheritsFrom`，117 个 libraries 全量），与用户自己那份《官方继承格式缺陷登记表》的结论一致——**继承链是缺陷来源，不是优雅**；
- 启动命令行标记：`-Dminecraft.launcher.brand=PCL`、`-Dminecraft.launcher.version=412`、`--versionType PCL`；
- `LatestLaunch.bat`：把最后一次真实命令行落成 bat（排障/复现利器，成本极低，价值极高）；
- `JavaWrapper.jar` + `libjlw-*.dll`：安装 Forge 时用 `com.bangbang93.ForgeInstaller` + `-Doolloo.jlw.tmpdir` 跑安装器（日志 17:08:57 实测），避免黑框/编码问题；游戏启动侧 `使用 JLW：False` 说明它是**可选**的；
- `使用 LUA：False` → LUA = `LwjglUnsafeAgent.jar`（`-javaagent`），针对 LWJGL 3.4.x 的兼容 workaround，非核心。

### 3.4 联机实现（这是本次最需要看清的一块）

| 维度 | 实测/枚举到的事实 |
|---|---|
| 组网 | EasyTier（`EasyTier CLI`、`准备下载联机模块` → `下载联机模块` → `启动联机模块`，**运行时下载，不随包分发**） |
| 房间模型 | 房主/成员；邀请码（"嘿，是否使用复制的邀请码加入房间？"）；"即将加入第三方联机房间" |
| 网络质量 | ping（`{0:0.0} ms`）、NAT 类型（`nat_type`）、是否中继（`relay`、`allow_relay`）、"正使用社区节点进行中继""正通过自定义节点进行中继" |
| 体验文案 | "你和房主的网络环境都不太好""你的网络环境比房主更好！如果你来当房主，其他玩家或许能更加流畅！""连接优化中" |

**结论**：联机的技术路线已经很清楚（P2P 组网 + 房间 + 中继回退），难点不在"能不能连"，在**NAT 穿透成功率、中继成本、以及"和正版登录/实例一致性怎么绑"**这三件事上。

## 4. 功能矩阵

**价值口径**：高 = 缺了它用户当天就用不下去/直接流失；中 = 影响留存或口碑；低 = 锦上添花。
**成本口径**：人日（1 人日 = 1 名熟悉 MC 启动链路的工程师 1 天），含自测不含 QA/设计；T 恤码 S≤5 / M≤10 / L≤15 / XL>15。
**归属**：P0 = GA 必须；P1 = parity 补齐（第二批）；P2 = 可延后/可选。

## 5. P0 验收标准（可复现）

**通用约定**

- 矩阵里的 17 个 P0 项按**可测试性**归并为 14 组验收：账户三态合为 P0-08；F16 自动进服并入 P0-09 的参数断言；
- 所有用例在一台 **Windows 11、16 GB 内存、100 Mbps 网络、全新空目录** 上执行，另需一台第二设备做联机对端；
- "通过"= 断言全部成立；任一断言失败即不通过，不允许"人工判断通过"；
- 证据三件套：**落盘文件**、**进程命令行**、**启动器日志**（每条断言都指明看哪一个）；
- 时间类阈值取 PCL 实测值的 1.5 倍（§3.1），留出硬件差异余量。

### P0-01 实例与版本管理

**前置**：准备 3 个实例：`vanilla-1.20.1`、`forge-1.20.1`（358 mods，1.5 GB）、`broken`（只有 `PCL\` 子目录，无同名 JSON）。

- **G**iven 上述目录，**W**hen 打开启动器首屏，**T**hen：三个实例全部出现在列表；`broken` 被标记为"无法识别/需修复"，点击不进启动流程；首屏可交互 ≤ 1.5 s（冷启动，SSD）。
- **W**hen 切换实例，**T**hen per-instance 的 Java、内存、隔离开关、图标被正确加载并回显（比对 `PCL\Setup.ini` 与 `config.json` 的实际值）。
- **W**hen 开启版本隔离，**T**hen 启动参数 `--gameDir` 指向 `versions\<实例>\`；关闭时指向 `.minecraft\`；切换时弹出"需手动迁移存档/Mod"的确认（不允许静默切换）。
- **W**hen 删除实例，**T**hen 二次确认中**列出将被删除的存档名与最后修改时间**；确认后目录被删除且不进回收站以外的地方；取消后目录零改动。
- **负向**：实例名含中文、空格、`[]`、`：`（本机 15 个实例中有 7 个含中文或全角符号，如 `Hunt：History 1949 - Blood Testament`、`[神道传说]GodRoad-人类群星闪耀时`、`史前世界 2`）——上述全部通过，且启动成功。

**证据**：列表截图、`--gameDir` 命令行、删除确认弹窗文本、日志中 `版本隔离：True/False`。

### P0-02 原版安装与修复

**前置**：空 `.minecraft`（无 `versions/`、无 `assets/`）。

- **W**hen 安装 1.20.1，**T**hen 产出 `versions\1.20.1\1.20.1.json` + `1.20.1.jar`；`assets\indexes\` 下出现对应 index；`libraries\` 下抽样 20 个 artifact 的 SHA1 与 JSON 一致；安装耗时 ≤ 8 min（PCL 同类操作实测约 60 s 量级，留 8 倍余量给国内网络波动）。
- **W**hen 手动删除 `libraries` 中任意 3 个 jar 后再次点启动，**T**hen 自动补齐且**只**重下缺失项（日志中下载条目数 ≤ 5），启动成功。
- **W**hen 安装中断网 30 s 再恢复，**T**hen 断点续传成功，最终 SHA1 校验通过，不出现"文件大小不一致"残留。
- **W**hen 点取消，**T**hen `versions\<目标>` 不残留半成品（对齐 PCL 的"由于下载失败或取消，清理版本文件夹"行为）。
- **负向**：安装一个不存在的版本号 → 明确报错，不创建空目录。

**证据**：目录树、SHA1 抽查结果、日志中的下载条目、取消后的目录快照。

### P0-03 Forge 安装

- **W**hen 安装 Forge 47.4.20（MC 1.20.1），**T**hen 产出 `versions\1.20.1-forge-47.4.20\` 下的 JSON（`mainClass = cpw.mods.bootstraplauncher.BootstrapLauncher`）+ 完整 libraries；启动成功进入主菜单；耗时 ≤ 6 min。
- **W**hen 查看产物 JSON，**T**hen **不含 `inheritsFrom`**（扁平化），`libraries` 数量 ≥ 100（对齐实测 117）。
- **W**hen 目标目录已存在同版本 Forge，**T**hen 提示覆盖/新建而非静默写入。
- **负向**：Java 版本过低（Java 8 装 1.20.1 Forge）→ 明确提示所需 Java 范围（对齐 `自动选择以下范围的 Java：[8.0.60, +∞)` 这种可读提示），不静默失败。

**证据**：JSON 片段、`mainClass`、启动日志的 `--launchTarget forgeclient`、耗时。

### P0-04 NeoForge 安装

**证据**：产物 JSON、启动成功、适配提示文案。

### P0-06 下载基础设施

- **W**hen 同一文件分别走"官方源"和"镜像源"，**T**hen 两者 SHA1 一致；坏源（人为指向一个 404 域名）被自动禁用并切源，最终成功。
- **W**hen 下载 500 MB 资源，**T**hen 支持 8 并发以上、可暂停/继续、可限速；进度误差 ≤ 2%。
- **W**hen 磁盘剩余空间不足，**T**hen 预检并明确提示所需空间，不产生半文件。
- **负向**：源返回 `Content-Length` 与实际不符 → 判为失败并切源（对齐 PCL 的 `ContentLength` 校验文案）。

**证据**：源切换日志、最终 SHA1、限速生效截图、空间不足提示。

### P0-07 Java 管理

- **前置**：机器上已有 Java 8/17/21/25 中的 3 套（注册表安装 + 绿色版各一）。
- **W**hen 打开设置，**T**hen 三套全部被识别（版本号、位数、路径正确）；**W**hen 安装 1.20.1，**T**hen 自动选中 17+（不选 8）；**W**hen 实例强制 Java 21，**T**hen 启动命令行使用该路径。
- **W**hen 机器上一个 Java 都没有，**T**hen 能拉取 Mojang 提供的 runtime 列表并自动下载安装（对齐 `SelectOrDownloadJava`），失败时给出"手动指定 Java"的退路。
- **负向**：Java 路径被删除后启动 → 提示"Java 不存在"并引导重选，不抛原始异常。

**证据**：Java 列表、`-XshowSettings` 输出、启动命令行、自动下载日志。

### P0-08 账户三态

- **离线**：**W**hen 用 `TestUser` 启动，**T**hen `--username TestUser`、`--uuid` 为合法 32 位 hex、`--userType legacy`（或 msa，按实现约定），进服成功。
- **微软**：**W**hen 首次登录，**T**hen 走设备码/回调完成授权，展示账号名与皮肤头；**W**hen 等待 token 过期后启动，**T**hen 自动刷新且用户无感；**W**hen 刷新失败，**T**hen 明确提示重新登录而不是"启动即崩"；**落盘检查**：token 不得明文（用字符串搜索配置文件，搜不到原文）。
- **Authlib**：**W**hen 配置 `LittleSkin` 类服务器（地址 + 名称 + 注册链接），**T**hen 启动命令行包含 `-javaagent:authlib-injector.jar=<api>`（或等价注入），游戏内显示第三方皮肤；**W**hen 服务器不可达，**T**hen 降级提示而不是卡死。
- **负向**：三态互切（微软 → 离线 → Authlib），每次切换后不得串号（UUID/用户名不得残留上一次的值）。

**证据**：进程命令行四件套、注入参数、配置文件字符串扫描结果、切换后的命令行。

### P0-09 启动链路与参数

**前置**：358 mod 的 Forge 实例。

- **W**hen 点启动，**T**hen 12 个阶段全部出现在日志中（预检测→…→结束处理），且阶段名可读；**W**hen 游戏进主菜单，**T**hen 总耗时 ≤ 125 s（PCL 实测 83 s：8.3 s 准备 + 4.5 s 窗口 + 70 s 材质）。
- **参数断言**（逐条比对命令行）：`-Xmx` 与设置一致；`-Djava.library.path` 指向实例内 natives；4 个 natives 相关 `-D` 齐全；`--gameDir` 正确；`--assetIndex` 与 JSON 一致；`-Dstdout.encoding`/`-Dfile.encoding` 与系统代码页匹配；无重复参数（`--width` 只出现一次）。
- **W**hen 实例配置了服务器地址与端口，**T**hen 命令行包含 `--server`/`--port`（1.20+ 优先 `--quickPlayMultiplayer`），且启动后直接进服；未配置时**不出现**该参数（不能瞎加）。
- **W**hen 修改内存为 4 GB 再启动，**T**hen 命令行 `-Xmx4G`（或 4096M），且启动成功。
- **W**hen Natives 目录被清空，**T**hen 自动重解压（对齐 PCL 的"删除后重解压"行为），启动成功。
- **W**hen 预启动处理执行，**T**hen `launcher_profiles.json` 被更新且包含当前实例；`options.txt` 的 `lang` 被设为实例要求值；**W**hen 双显卡机器，**T**hen 为 java.exe 设置高性能 GPU 偏好（注册表可查）。
- **负向**：实例 JSON 损坏 → 预检测阶段拦下并给出"重新安装/修复"入口，不进入启动。

**证据**：12 阶段日志、完整命令行、注册表项、`launcher_profiles.json`。

### P0-10 模组 / 资源包 / 光影基础管理

**证据**：渲染耗时、文件重命名结果、冲突提示、拖拽后的落盘路径。

### P0-11 整合包安装

**前置**：一个 Modrinth 格式 `.mrpack`（含 `overrides/`）、一个 CurseForge 格式 zip（含 `overrides/`）、一个带中文名的 zip。

**证据**：实例目录、`mods/` 数量与清单一致、启动成功、失败清单。

### P0-12 联机（分三级，逐级验收）

**L1 同局域网**（两台机器同一路由器）：

- **G**iven 双方同一实例（mod 列表哈希一致），**W**hen A 建房、B 用邀请码加入，**T**hen ≤ 15 s 内 B 显示"已连接"；A 开 LAN 世界后，B 能通过"多人游戏列表"或"房主 IP 直连"进入（两条路径任一必须 100% 可用，且 UI 明确告诉用户该点哪个）；游戏内延迟 ≤ 30 ms；**且**双方 mod 清单不一致时，加入前被拦截并列出差异（这条是我们的加分项，PCL 未见）。
- **L2 跨 NAT（双方均非对称型 NAT）**：5 组网络组合中 ≥ 4 组直连成功（≥ 80%），握手 ≤ 30 s。
- **L3 中继回退**：强制对称型 NAT，**T**hen ≤ 10 s 内切到中继并**明示**"正在通过中继连接"；延迟展示真实值（不美化）。
- **稳定性**：拔网线 10 s 再恢复，**T**hen 自动重连且不掉出世界（或明确提示"连接中断，已重连"）；房主退出，**T**hen 5 s 内所有成员收到"房间已关闭"。
- **负向**：邀请码错误/过期 → 明确提示，不无限转圈。

**证据**：两端日志、NAT 类型与中继标记、ping 采样、断线重连时间戳。

### P0-13 日志与崩溃报告

- **W**hen 游戏崩溃（人为删一个前置 mod 制造依赖缺失），**T**hen ≤ 10 s 内弹出报告；报告包含：崩溃时间、实例、Java、内存、最后 100 行日志、**至少 1 条可读结论**（如"缺失前置 mod：xxx"）。
- **W**hen 点"复制报告"，**T**hen 剪贴板得到纯文本（不是截图提示），且含可定位的文件路径。
- **W**hen 点"打开日志文件夹"，**T**hen 定位到实例 `logs/`。
- **落盘**：每次启动生成 `LatestLaunch.bat`（或等价"最后一次命令行"文件），内容可直接复现启动。
- **负向**：游戏正常退出（返回码 0）→ 不误报崩溃。

**证据**：报告文本、剪贴板内容、`LatestLaunch.bat`、误报检查。

### P0-14 更新器

- **W**hen 有新版本，**T**hen 检查到并展示版本号/更新说明；**W**hen 更新，**T**hen 下载→校验→替换→重启，旧版本保留可回滚；**W**hen 更新包校验失败，**T**hen 不替换、保留可用旧版。

- **负向**：更新过程中断电 → 下次启动仍可用旧版（原子替换）。

**证据**：版本号变化、回滚目录、断网时的启动耗时。

## 6. 非目标（P0 明确不做）

### 6.1 产品级不做（永久或长期）

| 不做的事 | 原因 | 何时重新讨论 |
|---|---|---|
| 盗版/绕过正版验证、伪造 session | 法律与生态底线，且会让我们进不了正版服务器生态 | 永不 |
| 自建 MC 下载的"规避通道" | 上游已因合规下架（公告 230），我们不能把合规风险转成产品功能 | 法务给出书面结论后 |
| 服务端托管/云开服/代部署 | 重资产业务，与"启动器"定位冲突；已有开服商在吃这块 | 有明确的商业化诉求时 |
| 启动器内社交/好友系统/大厅匹配 | 联机只需"房间+邀请码"，社交是另一个产品 | 联机留存数据证明需要 |
| 插件/脚本 API、第三方主题市场 | 生态冷启动成本极高，PCL 靠多年积累 | 用户量过 10 万 |
| 账号云同步、跨设备配置同步 | 涉及账号体系与隐私合规 | 有账号体系之后 |

### 6.2 P0 阶段不做（P1/P2 再做）

- **Quilt**（P2，PCL 只识别不安装，份额小）；
- **OptiFine / LiteLoader**（P1，兼容矩阵爆炸，先不碰）；
- **整合包导出**（P1，导入是刚需，导出是创作者需求）；
- **Mod 在线更新/下载/翻译**（P1/P2，先把"本地能跑"做稳）；
- **备份/还原**（P1，虽是最佳差异点，但不阻断主链路）；
- **服务器收藏列表 + ping/在线人数**（P1，P0 只做"启动即进服"）；
- **皮肤/披风上传**（P1，游戏内可换）；
- **主题/背景音乐/自定义 XAML 主页**（P1 基础主题，P2 自定义主页）；
- **帮助中心/反馈上传/公告投票**（P1，P0 只做本地日志与复制报告）；
- **崩溃规则库的深度诊断**（P0 只做 5 类高频：Java 版本不符、内存不足、缺失前置、Mod 冲突关键词、OpenGL/驱动）；
- **进程优先级、JLW、LUA（LWJGL agent）等兼容 workaround**（P2，遇到具体机型再说）。

### 6.3 工程级不做

- **只支持 Windows x64**（不做 macOS/Linux/ARM64；本机证据全是 Windows）；
- **只做简体中文**（不做多语言框架）；
- **不做免安装绿色版之外的安装器形态**（安装器只做"解压+快捷方式+卸载项"）；
- **不做多用户/多开隔离**（同一 Windows 用户一份配置）。
